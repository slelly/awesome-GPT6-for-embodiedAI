# 收录规则与证据方法

## 时间窗口不是日期猜测

主窗口为 **2026-08-18 至 2026-09-18（含两端），Asia/Taipei**。保留确切事件日期、来源所标日期和检查日期；三者不能互换。只有月份的条目标为 `month_only`，不补成 09-01。搜索结果“几天前”不自动转成首次发布日期。旧项目的本月 GPT-6 演示、代码更新与基础论文首发分别说明。

核心目录包含与主题直接相关但事件日期尚不完整的资源，故不能声称“12 个都在最近一个月首次发布”。HumanCLAW 等窗口外背景在 supporting 层明确标注。

## 来源等级

| 等级 | 可取得的证据 | 不意味着什么 |
| --- | --- | --- |
| A | 一手论文摘要、项目页、仓库正文或数据卡可读 | 不意味着实验被复现、代码完整、许可证允许任意用途 |
| B | 一手入口存在，但关键代码、评测正文或 GPT-6 关系未完整核实 | 不升级为完整可复现方案 |
| C | 可读的作者贴文镜像 / 转引作者声明 | 不等于登录原始 X 后核对过视频与时间戳 |
| D | 二手集合、媒体或缺原帖线索 | 不用于量化结果对比，不当成已确认成果 |

本快照来源等级 A/B/C/D 分别为 13/4/12/12。等级描述整条资源的**来源条件**；模型是否明确涉及 GPT-6，另看 `gpt6_relation`。例如基础设施可以为 A，但不能因此计入“GPT-6 成功实验数”。

原始访问方式保存在 `sources.json` 的 `access` 中：直接正文、搜索正文、局部索引或仅取得链接。搜索正文仍可能陈旧或截断；没有把它描述成克隆/审计了完整仓库。

## 模型角色与环境

每条分开记录 category、environment、control_interface：在线闭环、混合控制、分层工具调用、策略优化、离线 RL 工程、Real2Sim、几何动画重放、非交互理解评测与资源索引。视觉合理的动画不视作动力学有效；IK/waypoint/controller 提供的能力不全归给语言模型。

`explicit_primary` 表示可读一手资料明确涉及 GPT-6；`explicit_author_mirror` 是作者镜像；`reported_secondary` 是二手提及。`infrastructure`、`comparison_only`、`not_established`、`discovery_only` 不当成新的 GPT-6 控制结果。

## 去重与计分原则

同一项目的论文、GitHub、HF、视频和中文报道聚合到一条项目下。不同方法、数据版本或精选视频不冒充不同项目。HF 资源可以一对多关联，但不另加到项目总数中。AGP 旧 YAM 卡与 canonical 卡不能把 session 数直接相加。[S006](SOURCES.md#s006)、[S008](SOURCES.md#s008)

记录成绩时必须给出分母、环境、任务、成功判据与控制预算。只在协议能对齐时比较，不制作跨环境“综合排行榜”。Partial progress、native Score、VQA accuracy、full completion 各自保留；缺失分数不是 0。

`independently_reproduced=false` 在本快照全部成立。来源说“我们测试了”只代表原作者测试，不表示本仓库做过。

## 何时新增或升级

新增条目至少需要：稳定入口、模型角色、环境、日期依据、来源 ID、未决问题。优先补原帖、公开实现、完整失败日志和协议，而不是增加转发数量。只有实际可读到关键原始材料，才提高证据等级。记录修改原因，不抹去旧版的数据口径冲突。
